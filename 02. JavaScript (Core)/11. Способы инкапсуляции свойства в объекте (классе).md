# Способы инкапсуляции свойства в объекте (классе)

В JavaScript сейчас есть несколько основных техник инкапсуляции свойств, от «олдскульных» до современных, с разной степенью «настоящей приватности».

## 1. Договорённость по имени (`_prop`)

Самый старый и простой способ — считать свойства с подчёркиванием или другим префиксом приватными по договорённости:

```js
class User {
  constructor(name) {
    this._name = name; // "приватное по соглашению"
  }

  getName() {
    return this._name;
  }
}
```

Плюсы: легко, без магии, работает везде.
Минусы: свойство видно и доступно отовсюду, никакой реальной защиты нет.

## 2. Замыкания (closure)

«Канонический» старый способ инкапсуляции — хранить данные в лексическом окружении, а наружу отдавать только функции, которые его используют.

### Функциональный стиль

```js
function createCounter() {
  let count = 0; // приватное

  return {
    inc() {
      count++;
    },
    get() {
      return count;
    },
  };
}

const c = createCounter();
c.inc();
console.log(c.get()); // 1
// c.count недоступно
```

### Класс через замыкание

```js
function makePersonClass() {
  let privateAge = new WeakMap(); // см. ниже, можно и просто замыкание

  return class Person {
    constructor(name, age) {
      this.name = name;
      privateAge.set(this, age);
    }

    getAge() {
      return privateAge.get(this);
    }
  };
}

const Person = makePersonClass();
const p = new Person("Nikita", 30);
p.getAge(); // 30
// прямого доступа к age нет
```

Плюсы: реальная приватность, нельзя залезть из вне без хаков.
Минусы: неудобно сочетается с прототипами и наследованием, тяжело дебажить, иногда страдает читаемость.

## 3. `WeakMap` для приватных данных

Классический паттерн времен ES6: хранить приватные данные в `WeakMap`, где ключ — объект (экземпляр), значение — «приватное состояние».

```js
const _privates = new WeakMap();

class User {
  constructor(name, password) {
    this.name = name;
    _privates.set(this, { password });
  }

  checkPassword(pwd) {
    return _privates.get(this).password === pwd;
  }
}

const u = new User("Nikita", "secret");
// u.password нет
// но через методы доступ есть
```

Особенности:

- Ключи — только объекты, записи удаляются сборщиком мусора, когда объект недостижим.
- Свойства не висят на самом экземпляре.

Плюсы: довольно хорошая инкапсуляция, нормальная работа с классами.
Минусы: небольшая накладная стоимость, нестандартный паттерн, доступ возможен в любом месте, где видна сама `WeakMap` (это не «жёсткий» private).

## 4. `Symbol` как «почти приватный» ключ

Можно использовать `Symbol` как ключ скрытого свойства:

```js
const passwordSymbol = Symbol("password");

class User {
  constructor(name, password) {
    this.name = name;
    this[passwordSymbol] = password;
  }

  checkPassword(pwd) {
    return this[passwordSymbol] === pwd;
  }
}
```

Свойство не конфликтует с обычными строковыми ключами и не покажется в `for...in` / `Object.keys`.
Но:

```js
Object.getOwnPropertySymbols(u); // можно найти symbol-ключи
```

Плюсы: скрыто от «обычного» кода, нет коллизий по имени.
Минусы: это **обфускация**, а не строгая приватность, при желании доступен через reflection.

## 5. Геттеры/сеттеры и `Object.defineProperty`

Можно оставить поле «приватным по договорённости», но контролировать доступ через геттеры/сеттеры:

```js
function User(name) {
  let _name = name; // реально приватно (через замыкание)

  Object.defineProperty(this, "name", {
    get() {
      return _name;
    },
    set(value) {
      if (!value) throw new Error("Empty name");
      _name = value;
    },
  });
}
```

Или:

```js
const user = {};
let _age = 0;

Object.defineProperty(user, "age", {
  get() {
    return _age;
  },
  set(v) {
    if (v < 0) throw new Error("Age < 0");
    _age = v;
  },
  enumerable: true,
});
```

Плюсы: контроль доступа, валидация, единый интерфейс свойства.
Минусы: приватность зависит от того, где лежат настоящие данные (часто опять замыкание).

## 6. Современный синтаксис приватных полей (`#field`)

Нормализованный, «официальный» способ приватности для классов — приватные поля и методы с префиксом `#`:

```js
class User {
  #password; // приватное поле
  #checkInternal() {
    /* ... */
  } // приватный метод

  constructor(name, password) {
    this.name = name; // публичное
    this.#password = password; // приватное
  }

  checkPassword(pwd) {
    return this.#password === pwd;
  }
}

const u = new User("Nikita", "secret");
// u.#password; // SyntaxError
```

Ключевые особенности:

- Доступ к `#field` возможен только внутри тела того класса (и вложенных классов, определенных в том же лексическом окружении).
- Нельзя обратиться через строку, `this['#password']` не сработает.
- Приватность enforced на уровне спецификации и реализации движка.

Плюсы: настоящая «жёсткая» инкапсуляция, читаемый синтаксис, хорошая поддержка в современных движках.
Минусы: работает только в классах, не для «просто объектов»; нельзя динамически создать имя приватного поля.

Сюда же относится приватный статический элемент:

```js
class Counter {
  static #count = 0;

  static next() {
    return ++this.#count;
  }
}
```

## 7. Модульный паттерн / IIFE

Один из старых, но до сих пор встречающихся способов для «статических» данных — модульный паттерн через IIFE:

```js
const UserModule = (function () {
  const _secret = "token"; // приватно внутри модуля

  function getSecret() {
    return _secret;
  }

  return {
    getSecret,
  };
})();

UserModule.getSecret(); // 'token'
```

В современном коде это чаще заменяется на ES-модули, где «инкапсуляция» достигается через неэкспортированные сущности.

## 8. ES-модули (инкапсуляция на уровне файла)

В файле-модуле всё, что **не** экспортируется, по сути приватно для этого модуля:

```js
// user.js
const secretSalt = "abc"; // приватно: не экспортируем

export function hashPassword(pwd) {
  return pwd + secretSalt;
}
```

Из других файлов доступен только `hashPassword`, а `secretSalt` недоступен напрямую.

Плюсы: естественно, хорошо ложится на архитектуру.
Минусы: приватность — на уровне модуля, а не отдельного экземпляра объекта.

---

Если кратко по «новые и старые»:

- Старые/исторические:
  - договорённость по имени (`_prop`);
  - замыкания (фабрики, модульный паттерн, геттеры/сеттеры с замыканием);
  - `Object.defineProperty`;
  - `Symbol` для «скрытых» свойств;
  - `WeakMap` для приватного состояния объектов.
- Современные:
  - приватные поля/методы классов (`#field`, `#method`, в т.ч. статические);
  - инкапсуляция через ES-модули (неэкспортируемые сущности).

Если хочешь, могу набросать сравнение этих подходов именно в контексте «продакшн‑friendly» кода в 2026 (что выбирать под Node, браузеры, либы, SDK и т.п.).
