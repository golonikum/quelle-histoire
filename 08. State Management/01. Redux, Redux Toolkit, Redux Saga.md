# 🎯 Redux, Redux Toolkit, Redux Saga

### **📦 Redux — Центральный склад данных**

**Представь:** У тебя магазин. Вместо того чтобы каждый продавец хранил свой список товаров, **всё в одном складе**. Продавцы только **запрашивают** данные и **отправляют записки** "добавить товар/убрать товар".

```
State (склад): { cart: 5, user: 'Иван', total: 2500 }
↓
Action (записка): { type: 'ADD_TO_CART', payload: {item: 'iPhone'} }
↓
Reducer (кладовщик): новый_state = старый_state + iPhone
↓
Компоненты получают обновление
```

**3 правила:**

1. **Единственный store** — все данные в одном месте
2. **Только actions** — изменения только через записки
3. **Чистые reducers** — кладовщик всегда возвращает новый объект

### **⚡ Redux Toolkit — Redux без боли (официально рекомендуется!)**

**Проблемы чистого Redux:**

```
❌ 300 строк кода для простого счётчика
❌ Много boilerplate (actions, action types, switch)
❌ Immer мутации вручную
```

**Redux Toolkit решает:**

```js
// ✅ 10 строк вместо 300!
import { createSlice, configureStore } from "@reduxjs/toolkit";

const counterSlice = createSlice({
  name: "counter",
  initialState: 0,
  reducers: {
    increment: (state) => state + 1, // Автоматически мутируем!
    decrement: (state) => state - 1,
  },
});

export const { increment, decrement } = counterSlice.actions;
```

### **🔄 Redux Saga — Босс асинхронных операций**

**Проблема:** Redux не умеет `fetch`, таймеры, WebSocket. Нужно thunk/middleware.

**Saga = генераторы + эффекты** (как оркестратор):

```
Saga говорит: "Сначала fetch → потом покажи loader → сохрани в store → спрячь loader"
```

**Простой пример:**

```js
// ✅ Saga вместо thunk
function* fetchUserSaga(action) {
  try {
    yield put({ type: "LOADING_START" }); // Показать loader
    const user = yield call(api.fetchUser, action.id); // fetch
    yield put({ type: "USER_SUCCESS", user }); // В store
  } catch (error) {
    yield put({ type: "USER_ERROR", error }); // Обработка ошибки
  }
}
```

## 📊 **Сравнение (когда что использовать)**

| Инструмент | Зачем                      | Сложность | Пример                |
| :--------- | :------------------------- | :-------- | :-------------------- |
| **Redux**  | Централизованное состояние | ⭐⭐⭐⭐  | Корзина, пользователи |
| **RTK**    | Redux + меньше кода        | ⭐⭐      | 95% React проектов    |
| **Saga**   | API, таймеры, WebSocket    | ⭐⭐⭐⭐  | Сложная бизнес-логика |

## 🎬 **Полный пример (Корзина магазина)**

```jsx
// 1. Redux Toolkit Slice
const cartSlice = createSlice({
  name: "cart",
  initialState: { items: [], loading: false },
  reducers: {
    addItem: (state, { payload }) => {
      state.items.push(payload);
    },
    setLoading: (state, { payload }) => {
      state.loading = payload;
    },
  },
});

// 2. Redux Saga
function* addToCartSaga({ payload }) {
  yield put(setLoading(true));
  const item = yield call(api.fetchItem, payload.id);
  yield put(addItem(item));
  yield put(setLoading(false));
}

// 3. Компонент
function Cart() {
  const { items, loading } = useSelector((state) => state.cart);
  const dispatch = useDispatch();

  return (
    <div>
      {loading && <Spinner />}
      <button onClick={() => dispatch(addToCart({ id: 1 }))}>
        Добавить товар
      </button>
    </div>
  );
}
```

# Redux Saga Runtime — детальный разбор "под капотом"

Давайте разберем **полный цикл** выполнения саги с псевдокодом реального runtime.

## 1. Saga Middleware Инициализация

```javascript
// При создании store
const sagaMiddleware = createSagaMiddleware();
const store = createStore(
  reducer,
  applyMiddleware(sagaMiddleware, thunkMiddleware),
);

// Запуск rootSaga
sagaMiddleware.run(rootSaga);
```

**Что делает `run()`:**

```javascript
function run(rootSaga) {
  const task = proc(rootSaga, null, resolveMainTask); // Создает Task
  task.done.then((rootTask) => {
    console.error("Root saga died!"); // Перезапуск при ошибке
  });
  return task;
}
```

## 2. proc() — Основной интерпретатор

```javascript
// proc — сердце саги, управляет выполнением generator
function proc(iterator, parentContext, onDone) {
  const context = {
    task: { context, cancel: noop }, // Task descriptor
    store,
    channel: stdChannel, // Action broadcaster
  };

  // Запуск генератора
  const task = new Task(context, iterator, onDone);
  task.cont = (isErr, arg) => {
    if (isErr) {
      resolveErr(iterator, arg, task.cont);
    } else {
      next(iterator, arg, task.cont);
    }
  };

  task.cont(); // Первый next()
  return task;
}
```

## 3. Task Lifecycle

```javascript
class Task {
  constructor(context, iterator, onDone) {
    this.iterator = iterator;
    this.context = context;
    this.isRunning = true;
    this.onDone = onDone;
  }

  cont(isErr, arg) {
    try {
      const { value: effect, done } = isErr
        ? this.iterator.throw(arg)
        : this.iterator.next(arg);

      if (done) {
        this.onDone(effect); // Завершение саги
      } else {
        runEffect(effect, this.cont); // Обработка следующего yield
      }
    } catch (err) {
      this.onDone(err);
    }
  }
}
```

## 4. runEffect() — Dispatch эффектов

```javascript
function runEffect(effect, cb) {
  if (isTake(effect)) {
    // Блокирует до action
    channel.once(effect.action, cb);
  } else if (isCall(effect)) {
    // Выполняет асинхронную функцию
    effect
      .fn(...effect.args)
      .then((result) => cb(false, result))
      .catch((err) => cb(true, err));
  } else if (isPut(effect)) {
    // Немедленный dispatch
    store.dispatch(effect.action);
    cb(false, undefined); // Продолжаем
  } else if (isFork(effect)) {
    // Параллельный запуск
    const childTask = proc(effect.iterator);
    cb(false, childTask);
  }
}
```

## 5. Channel (take/put коммуникация)

```javascript
class Channel {
  constructor() {
    this.listeners = new Map(); // pattern → [callbacks]
  }

  put(action) {
    const callbacks = this.listeners.get(action.type) || [];
    callbacks.forEach((cb) => cb(action));
    this.listeners.delete(action.type);
  }

  take(pattern, cb) {
    const matcher = createMatcher(pattern);
    this.listeners.set(pattern, [...(this.listeners.get(pattern) || []), cb]);
  }
}
```

## 6. Полный пример выполнения

```javascript
function* fetchUserSaga(action) {
  const user = yield call(fetchUserApi, action.id); // ①
  yield put({ type: "SUCCESS", user }); // ②
  const settings = yield select((state) => state.settings); // ③
  yield take("LOGOUT"); // ④
}

const task = proc(fetchUserSaga);

// Шаг ①: call(fetchUserApi)
runEffect({ fn: fetchUserApi, args: [action.id] }, cont);
fetchUserApi().then((user) => cont(false, user));

// Шаг ②: put(SUCCESS)
runEffect({ action: { type: "SUCCESS", user } }, cont);
store.dispatch(action);
cont(false, undefined);

// Шаг ③: select
runEffect({ selector: (state) => state.settings }, cont);
cont(false, settings);

// Шаг ④: take(LOGOUT)
runEffect({ pattern: "LOGOUT" }, cont);
channel.take("LOGOUT", cont);
```

## 7. Параллельность (fork vs call)

```javascript
// call — блокирует родителя
function* serial() {
  const a = yield call(fn1); // Ждет!
  const b = yield call(fn2); // Ждет!
}

// fork — НЕ блокирует
function* parallel() {
  yield fork(fn1); // Фоновая задача
  yield fork(fn2); // Фоновая задача
  yield take("DONE"); // Ждет завершения
}
```

## 8. Отмена (cancel)

```javascript
function* watchRequests() {
  const task = yield fork(fetchUserSaga);

  yield take("CANCEL");
  yield cancel(task); // Останавливает fetchUserSaga
}

function* fetchUserSaga() {
  try {
    const user = yield race({
      user: call(fetchUserApi),
      cancel: take("CANCEL_USER"),
    });
  } catch (cancelled) {
    console.log("Запрос отменен");
  }
}
```

## 9. Memory Model

```
Channel (Event Bus)
├── Listeners: Map<pattern, [cb1, cb2]>
├── Queue: [] (buffered channel)

Task Tree
RootSaga
├── watchFetch (fork)
│   └── fetchUser1 (fork)
│       └── call(API)
├── watchSearch (fork)
│   └── searchSaga (fork)
└── rootTask.done
```

## 🔍 Ключевые insights

1. **Генератор = FSM** (Finite State Machine)
2. **Saga runtime = интерпретатор байткода**
3. **Channel = встроенный EventEmitter**
4. **Task = объект с отменой + контекстом**
5. **Effects = AST узлы для интерпретатора**

## Performance детали

```
+ Маленький runtime (~25kb)
+ Предсказуемый scheduling
+ Нет Promise chaining overhead
- Генераторы медленнее async/await (x1.5-2)
```

**Собес уровень:** Redux Saga = **Coroutine library** на генераторах + **Actor model** (channel). Понимаешь generator iterator protocol → понимаешь 90% магии.

# Архитектурные паттерны в Redux Saga

Redux Saga реализует несколько классических паттернов проектирования **под капотом**. Вот полный список:

## 1. **Interpreter Pattern** ⭐⭐⭐ (главный)

```
Generator Effects = AST → Saga Runtime интерпретирует
yield take()      → parseTakeEffect(effect)
yield call(fn)    → parseCallEffect(effect)
yield put(action) → parsePutEffect(effect)
```

**Saga runtime** = интерпретатор "байткода" генераторов. Каждый `yield effect` — узел абстрактного синтаксического дерева.

## 2. **Actor Model** (Channel)

```
Channel = Actor (Event Bus)
├── Listeners: Map<pattern, Queue<callback>>
├── put(action) → notify all matching actors
└── take(pattern) → suspend actor до события
```

**Channel** — это актор, который маршрутизирует сообщения (actions) между задачами. `takeEvery`/`takeLatest` = mailbox patterns.

## 3. **Saga Pattern** (Compensating Transactions)

```
fetchUser → processPayment → sendEmail
  ↓ error       ↓ error        ↓ error
cancelAll ←←←←←←←←←←←←←←←←←←←
```

**Компенсирующие действия** при ошибках: `cancel(task)` откатывает всю цепочку.

## 4. **Coroutine / Cooperative Multitasking**

```
Task = Lightweight Thread (кооперативный)
proc(iterator) → yield → pause → resume → yield → pause...
```

Каждая сага — **легковесный поток** с явными точками паузы (`yield`).

## 5. **Observer Pattern** (Watcher Saga)

```javascript
function* watchFetchUser() {
  while (true) {
    const action = yield take("FETCH_USER"); // Observer
    yield fork(fetchUserSaga, action); // Notify → spawn worker
  }
}
```

**Watcher** наблюдает за Redux store, **worker** реагирует.

## 6. **Command Pattern** (Effects)

```
take/call/put/fork = Commands для runtime
effect = { type: 'CALL', fn, args }
runEffect(effect) → executeCommand(effect)
```

Каждый effect — **команда** с инверсией управления (Hollywood Principle).

## 7. **Composite Pattern** (Saga Tree)

```
RootSaga (Composite)
├── watchUsers (Leaf)
├── watchOrders (Leaf)
└── watchAuth (Composite)
    ├── loginSaga (Leaf)
    └── logoutSaga (Leaf)
```

**Дерево задач**: `fork()` создает иерархию родитель-ребенок.

## 8. **Strategy Pattern** (take\* helpers)

```javascript
takeEvery = strategy.concurrent();
takeLatest = strategy.cancelPrevious();
takeLeading = strategy.firstComeFirstServed();
```

**Разные стратегии** обработки событий через один интерфейс `take()`.

## 9. **Finite State Machine (FSM)**

```
Saga State: RUNNING → YIELDING → SUSPENDED → RESUMED
Transition: yield effect → runEffect() → next(cont)
```

**Генератор** = FSM с состояниями `iterator.next/throw/return`.

## 10. **Supervisor Pattern** (Error Boundaries)

```javascript
function* rootSaga() {
  try {
    yield fork(watchUser);
    yield fork(watchOrder);
  } catch (error) {
    yield put(showError(error)); // Supervisor перехватывает
  }
}
```

**RootSaga** = supervisor, который перезапускает/логирует падшие задачи.

## 11. **Event Sourcing** (Action Log)

```
Каждый put(take/call) = Event в логе
channel.put(action) → append to event stream
take(pattern) → replay matching events
```

## Визуализация архитектуры

```
┌─────────────────┐    ┌──────────────┐
│   Redux Store   │◄──►│ Saga Channel │
└─────────┬───────┘    └───────┬──────┘
          │                    │
    dispatch(action)      takeEvery(pattern)
          │                    │
┌─────────▼──────┐    ┌────────▼──────┐
│   Reducer      │    │   proc()      │ ← Interpreter
└────────────────┘    └─────┬─────────┘
                            │
                       ┌────▼───────┐
                       │ Generator* │ ← Coroutine
                       │ yield eff. │
                       └────┬───────┘
                            │
                     ┌──────▼──────┐
                     │ runEffect() │ ← Command Dispatcher
                     └──────┬──────┘

                   call/fork/put/select
```

## 🎯 Собес cheat sheet

```
1. **Interpreter**: Effects → runtime
2. **Actor**: Channel как message bus
3. **Saga**: Compensating transactions
4. **Coroutine**: yield/resume модель
5. **Composite**: Task tree (fork/join)
6. **Observer**: watch* → worker
7. **Command**: Effects как команды
8. **Strategy**: takeEvery/Latest/Leading
```

**Вывод:** Redux Saga = **оркестратор корутин** с **event-driven архитектурой** + **композируемыми командами**. RTK Query проще, но Saga выигрывает в workflow complexity.
