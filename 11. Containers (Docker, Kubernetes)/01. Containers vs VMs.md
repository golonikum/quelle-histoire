# Основы контейнеризации

**Контейнеризация в Linux** использует механизмы ядра (**namespaces + cgroups**) для изоляции **процессов приложения + его зависимостей** без полной ОС. **VM** запускает полноценную гостевую ОС с гипервизором.

## Основные механизмы Linux (ядро 2.6.24+)

### **1. Namespaces — изоляция пространства имён**

```
PID: каждый контейнер думает что PID=1
NET: отдельная сеть (bridge/veth)
MNT: изолированная файловая система
UTS: свой hostname/domainname
USER: свой root (uid=0)
IPC: изолированная межпроцессная связь
```

### **2. Cgroups — контроль ресурсов**

```
CPU: лимит 200% = 2 ядра
Memory: 4GB soft limit
BlkIO: 100 IOPS на диск
Network: 1Gbps bandwidth
```

## Контейнеры vs VM — ключевое сравнение

| Аспект            | **Контейнеры**       | **Виртуальные машины**   |
| :---------------- | :------------------- | :----------------------- |
| **Архитектура**   | **Общее ядро Linux** | Отдельная гостевая ОС    |
| **Размер**        | **10–100 МБ**        | **2–20 ГБ**              |
| **Запуск**        | **<1 сек**           | **30 сек – 5 мин**       |
| **Ресурсы**       | **5–10% overhead**   | **20–50% overhead**      |
| **Изоляция**      | Процессы (слабая)    | **Полная (железо)**      |
| **Портативность** | Любой Linux хост     | Только тот же гипервизор |

## Как докер работает на Windows

**Docker на Windows** работает через **виртуальную машину Linux** (WSL2 или Hyper-V), поскольку **нативные Linux namespaces/cgroups отсутствуют** в ядре Windows.

### 2 режима работы Docker Desktop

#### **1. WSL2 (рекомендуется, 95% случаев)**

```
Windows → Docker Desktop → WSL2 VM (Ubuntu) → Docker Daemon + контейнеры
```

- **Linux-контейнеры** (Node.js, PostgreSQL, Redis)
- **Прозрачная интеграция** с Windows (shared volumes)
- **Автоматическая установка** Ubuntu в WSL2

#### **2. Hyper-V (Windows-контейнеры)**

```
Windows → Docker Desktop → Hyper-V VM → Windows Server Core → Контейнеры
```

- Только **Windows-контейнеры** (.NET, IIS)
- Тяжёлый overhead (~4 ГБ RAM)

### Установка (Windows 11, 2026)

```powershell
# 1. Включить WSL2 + виртуализацию
dism.exe /online /enable-feature /featurename:Microsoft-Windows-Subsystem-Linux /all /norestart
disl.exe /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart

# 2. Установить WSL2 kernel
wsl --install

# 3. Docker Desktop (EXE с сайта)
# Выбрать "Use WSL2 instead of Hyper-V" → Install
```

### Архитектура под капотом

```
Windows GUI ←→ Docker CLI ←→ Docker Desktop ←→ WSL2 VM
                                                      ↓
                                              Docker Daemon (dockerd)
                                                      ↓
                                            Linux Containers (namespaces)
```

**WSL2 VM** (~500 МБ):

```
Ubuntu 20.04 minimal
Docker Engine 27.x
docker-compose
NFS server (shared volumes)
```

### Ограничения Windows vs Linux

| Проблема             | Windows Docker           | Linux Docker |
| :------------------- | :----------------------- | :----------- |
| **Запуск**           | **20–40 сек**            | **2–5 сек**  |
| **Файловая система** | **x10 медленнее** (NTFS) | ✅ ext4      |
| **Build время**      | **x3–x5**                | ✅           |
| **Memory overhead**  | **~1 ГБ**                | **~100 МБ**  |

### Оптимизация для разработки

```powershell
# 1. Использовать WSL2 distro напрямую
wsl -d Ubuntu
cd /mnt/c/Projects/apk
docker build -t apk .

# 2. Docker Buildx (мультиплатформенный)
docker buildx build --platform linux/amd64 -t apk:latest .
```

**Вывод**: Docker на Windows **работает отлично для разработки** через WSL2 (95% Linux-контейнеров). Production — Linux серверы. Разница в скорости заметна только при больших монтированиях.
