# Настройка почтового сервера на Ubuntu (Stalwart)

Инструкция для Ubuntu 22.04/24.04. Везде замените `plantlapse.com` на ваш домен, а `mail.plantlapse.com` на имя почтового хоста. Все команды выполняются от root или через `sudo`.

## 0. Что нужно заранее

- VPS с публичным статическим IP.
- Домен, DNS которого вы можете редактировать.
- **Открытый порт 25.** Многие хостеры блокируют его по умолчанию, и тогда его нужно разблокировать через поддержку.
- **PTR-запись** (обратный DNS) для IP сервера на `mail.plantlapse.com`. Её настраивают в панели хостера, без неё письма уйдут в спам.

## 1. Подготовка системы

```bash
sudo apt update
sudo apt upgrade -y
hostnamectl set-hostname mail.plantlapse.com
echo "127.0.1.1 mail.plantlapse.com mail" | sudo tee -a /etc/hosts

sudo ufw allow 22,25,80,443,465,587,993,4190/tcp
sudo ufw enable
```

## 2. DNS-записи (первая часть)

Создайте у регистратора или DNS-провайдера:

| Тип | Имя    | Значение                             |
| --- | ------ | ------------------------------------ |
| A   | `mail` | IP сервера                           |
| MX  | `@`    | `mail.plantlapse.com` (приоритет 10) |

## 3. TLS-сертификат

```bash
apt install certbot -y
certbot certonly --standalone -d mail.plantlapse.com
```

Сертификаты окажутся в `/etc/letsencrypt/live/mail.plantlapse.com/`.

## 4. Stalwart Mail Server

`Stalwart` написан на Rust и совмещает SMTP, IMAP, POP3, JMAP, DKIM/SPF/DMARC, антиспам и веб-админку в одном бинарнике.

Описание соответствует документации Stalwart 0.16 на момент 30.10.2026. Установщик и мастер настройки менялись между версиями, так что при расхождениях ориентируйтесь на официальную страницу https://stalw.art/docs/install/platform/linux/.

### A. Важное перед началом

Откройте в firewall порты, если они раньше не были открыты:

```bash
ufw allow 25,80,443,465,587,993,4190/tcp
```

Порт 443 нужен для веб-интерфейса и выпуска сертификата, 4190 для ManageSieve (серверные фильтры писем).

### B. Установка

```bash
curl --proto '=https' --tlsv1.2 -sSf https://get.stalw.art/install.sh -o install.sh
sudo sh install.sh
```

Скрипт скачает последний релиз, создаст отдельного системного пользователя `stalwart`, поставит бинарник в `/usr/local/bin/stalwart`, зарегистрирует systemd-службу и запустит её.

Файлы после установки:

| Что                  | Где                                                  |
| -------------------- | ---------------------------------------------------- |
| Конфигурация         | `/etc/stalwart/config.json` (появится после мастера) |
| Переменные окружения | `/etc/stalwart/stalwart.env`                         |
| Данные               | `/var/lib/stalwart/`                                 |
| Логи                 | `/var/log/stalwart/`                                 |

### C. Первый вход и мастер настройки

При первом запуске конфигурации ещё нет, поэтому сервер работает в режиме начальной настройки (bootstrap) и отдаёт только мастер на порту 8080 по обычному HTTP. Он создаёт временного администратора `admin` со случайным паролем. Пароль печатается один раз в вывод службы:

```bash
sudo journalctl -u stalwart -n 200 | grep -A8 'bootstrap mode'
```

Пароль меняется при каждом старте, поэтому берите самый свежий блок.

**Порт 8080 без шифрования, поэтому не открывайте его в интернет.** Безопаснее пробросить его через SSH-туннель с вашего компьютера:

```bash
ssh -L 8080:localhost:8080 user@mail.plantlapse.com
```

Затем откройте в браузере `http://localhost:8080/admin` и войдите как `admin` с временным паролем.

#### Экраны мастера

1. **Server identity.** Введите **Server Hostname** (`mail.plantlapse.com`) и **Default Email Domain** (`plantlapse.com`). Мастер подставит значения из имени машины, так что проверьте оба поля. Обе галочки (автоматический TLS-сертификат от Let's Encrypt и генерация DKIM-ключей) оставьте включёнными.
2. **Storage.** Оставьте значения по умолчанию: встроенная база RocksDB в `/var/lib/stalwart/`, отдельный сервер БД не нужен.
3. **Directory.** Выберите внутренний каталог (_internal directory_). Учётные записи будут храниться в самом Stalwart.
4. **Logging.** Оставьте запись в файл (`/var/log/stalwart/`).
5. **Automatic DNS management.** Здесь два варианта:
   - **Выбрать вашего DNS-провайдера** (Cloudflare, Route 53, Google Cloud DNS или любой сервер с RFC 2136) и указать API-токен. Тогда Stalwart сам создаст и будет обновлять SPF, DKIM, DMARC, MTA-STS, SRV и autoconfig-записи, а сертификат получит через DNS-01 без входящих подключений. DKIM-ключи при этом будут автоматически ротироваться.
   - **Ручное управление.** Подходит, если провайдер не поддерживается. Тогда DKIM не ротируется, а для сертификата заранее нужны CNAME-записи `mta-sts`, `autoconfig`, `autodiscover` и `ua-auto-config` на `mail.plantlapse.com` и доступный порт 443.

После нажатия **Finish setup** на последнем экране покажут логин `admin@plantlapse.com` и новый пароль. **Сохраните его сразу**: повторно он не отображается и в лог не пишется.

### D. Перезапуск и вход в веб-интерфейс

```bash
sudo systemctl restart stalwart
```

После перезапуска сервер выходит из режима настройки и запускает почтовые службы. Админка теперь доступна только по HTTPS на hostname сервера: `https://mail.plantlapse.com/admin`. Вход по IP-адресу или через порт 8080 в обычном режиме не работает.

Сразу после старта сертификата может ещё не быть, и браузер покажет предупреждение. Не принимайте его, подождите несколько минут и обновите страницу: сначала сервер публикует DNS-записи, потом запрашивает сертификат.

### E. DNS

- **С автоматическим управлением:** Stalwart опубликует почти все записи сам. Вручную нужно добавить только **MX**: `plantlapse.com. MX 10 mail.plantlapse.com.`
- **Без автоматического:** в веб-интерфейсе откройте Management › Domains, выберите ваш домен, затем **View Zone File**. Это готовый файл в формате BIND, который можно импортировать целиком или переносить запись за записью.

Проверка:

```bash
dig +short @1.1.1.1 MX plantlapse.com
dig +short @1.1.1.1 TXT plantlapse.com
dig +short @1.1.1.1 TXT _dmarc.plantlapse.com
```

Если у домена уже есть SPF-запись от прежнего почтовика, оставьте только одну запись, начинающуюся с `v=spf1`. Две записи ломают SPF для всего домена. Кроме того, пока MX указывает на старого провайдера, почта продолжает идти ему.

### F. Создание пользователя

Аккаунт `admin` предназначен только для администрирования, для почты заведите отдельного пользователя:

1. В веб-интерфейсе откройте Management › Directory › Accounts и создайте аккаунт, например `anna`, домен `plantlapse.com`.
2. Пароль добавляется не в основной форме, а в разделе **Authentication › Credentials** кнопкой **Add item**. Минимальная длина по умолчанию 8 символов.
3. Проверьте вход на `https://mail.plantlapse.com/account` с полным адресом `anna@plantlapse.com`.

### G. Настройка почтового клиента

| Параметр | Значение                                 |
| -------- | ---------------------------------------- |
| IMAP     | `mail.plantlapse.com`, порт 993, SSL/TLS |
| SMTP     | `mail.plantlapse.com`, порт 465, SSL/TLS |
| Логин    | полный адрес `anna@plantlapse.com`       |

Thunderbird и подобные клиенты найдут настройки сами благодаря autoconfig-записям. Отправьте письмо на внешний ящик и ответьте на него. В заголовках полученного письма SPF, DKIM и DMARC должны быть в статусе `pass`. Затем прогоните тест на mail-tester.com, как в основной инструкции.

### H. Закрепление после настройки

1. **Уберите открытый HTTP-листенер на 8080**, если он не нужен для обратного прокси.
2. **Удалите `STALWART_RECOVERY_ADMIN`** из `/etc/stalwart/stalwart.env`, если вы его задавали.
3. Просмотрите рекомендации на странице Securing the server (https://stalw.art/docs/install/security).
4. Автоблокировка (auto-ban) включена по умолчанию: после множества неудачных входов адрес блокируется. Если заблокировали себя, смотрите раздел Auto-ban в документации.

Для обновлений и бэкапов используйте разделы Upgrading и Backup and restore в документации. Бэкап данных нужно делать из `/var/lib/stalwart/` (при остановленной службе или средствами самого Stalwart).

### I. Типичные проблемы

- **Служба не стартует или порт не открывается.** Скорее всего, порт 25 занят Postfix или Exim. Остановите и отключите их (`systemctl disable --now postfix`).
- **`/admin` отвечает 404.** Сервер скачивает веб-интерфейс с GitHub при первом старте. Проверьте, что исходящий HTTPS не заблокирован.
- **Ошибки `Unknown client id` или `Client metadata documents are disabled`.** Вы открыли админку не по `https://<hostname>/admin`. Используйте именно hostname из мастера.
- **Предупреждение о сертификате не исчезает.** Проверьте DNS-токен и права на зону. Пока записи не опубликованы, сертификат не запрашивается. Журнал: `/var/log/stalwart/stalwart.log.<дата>`.
- **Письма висят в очереди с `Connection timeout`.** Хостер блокирует исходящий порт 25. Попросите снять блокировку либо настройте отправку через relay-хост.
- **Письма попадают в спам.** Проверьте PTR, SPF/DKIM/DMARC и чёрные списки IP, как в разделе «Частые проблемы» основной инструкции.
- **Вход в мастер не работает после перезапуска.** Пароль меняется при каждом старте в режиме настройки, берите самый свежий из `journalctl`. Если нужен известный пароль, задайте `STALWART_RECOVERY_ADMIN=admin:<пароль>` в `stalwart.env` и перезапустите службу (потом переменную нужно удалить).

## 5. Чтобы на этом сервере еще был сайт

Почта и сайт на одном VPS вполне совместимы. Главное, что нужно учесть заранее: **Stalwart и сайт по умолчанию претендуют на одни и те же порты 80 и 443**, а Docker по-своему обходит `ufw`.

### Как лучше разделить

- **Stalwart ставьте на хост, как мы делали**, без Docker. Почтовым портам (25, 465, 993) нужно видеть настоящие IP клиентов, а Docker с NAT это усложняет.
- **Сайт запускайте в Docker.** Перед ним ставится один обратный прокси (Caddy), который принимает 80/443 и раздаёт трафик по имени домена:

```
plantlapse.com, www.plantlapse.com  →  Caddy  →  контейнер с сайтом
mail.plantlapse.com (веб-админка)   →  Caddy  →  Stalwart (HTTP)
порты 25, 465, 587, 993, 4190       →  напрямую в Stalwart
```

Caddy сам получает и обновляет HTTPS-сертификаты для сайта. В документации Stalwart Caddy, nginx, HAProxy и Traefik перечислены как совместимые прокси.

### Две ловушки

**1. Конфликт портов.** Пока Stalwart держит 443, Caddy не запустится. Поэтому в Stalwart нужно перенести HTTPS-листенер на другой порт (или пустить Caddy на его HTTP-листенер), а в окружении указать публичный адрес через `STALWART_PUBLIC_URL=https://mail.plantlapse.com`. Точные названия настроек в версии 0.16 смотрите в документации: https://stalw.art/docs/server/reverse-proxy/ (разделы про Caddy и Proxy Protocol). Я не проверял их построчно и не хочу давать вам непроверенный конфиг, от которого может отвалиться вход в админку.

**2. Сертификат для почтовых портов.** Когда 80/443 занимает Caddy, Stalwart не сможет подтвердить домен через HTTP-01 и TLS-ALPN-01. Решения такие:

- **Автоматическое управление DNS** на экране 5 мастера (если ваш DNS-провайдер в списке поддерживаемых, например Cloudflare). Тогда сертификат подтверждается через DNS-01 и не зависит от портов 80/443. Это самый простой вариант.
- Если провайдера в списке нет, придётся копировать сертификат из Caddy в Stalwart (схема есть в документации Stalwart к Caddy). Это работает, но хлопотнее.
- Второй публичный IP: Stalwart на одном, сайт на другом. Тогда конфликта нет вообще.

### Docker и ufw

Опубликованные порты контейнеров (`-p 8080:80`) Docker открывает в обход правил `ufw`, так что сервис станет доступен всему интернету. Поэтому публикуйте порты только на localhost:

```yaml
ports:
  - "127.0.0.1:8081:80"
```

Для самого Caddy проще всего `network_mode: host`: он тогда нормально видит `127.0.0.1` (где слушает Stalwart), и `ufw` на него действует как обычно.

### Порядок действий

1. **Сначала поднимите почту** по инструкции Stalwart, с автоматическим DNS, если это возможно. Убедитесь, что письма ходят в обе стороны.
2. Установите Docker из официального репозитория (`docker-ce` и плагин `docker compose`, не `docker.io` из Ubuntu).
3. Переведите Stalwart за прокси (см. ловушку 1).
4. Поднимите Caddy и контейнер с сайтом через `docker compose`.
