# CSS content visibility

`content-visibility` — это CSS-свойство, которое позволяет браузеру **пропускать рендеринг элемента**, пока он не нужен пользователю. Чаще всего используют `content-visibility: auto`, чтобы ускорить длинные страницы: браузер не делает layout и paint для контента вне экрана, а дорисовывает его только при приближении к viewport.

## Основная идея

Если элемент далеко за пределами экрана, браузер может не тратить на него ресурсы. Это особенно полезно для длинных лент, комментариев, больших секций статьи и тяжёлых карточек, где на первом экране видна только малая часть контента.

## Основные значения

- `visible` — обычное поведение, всё рендерится сразу.
- `hidden` — элемент не отображается, но состояние рендеринга сохраняется, чтобы потом быстро показать его снова.
- `auto` — браузер сам решает, когда рендерить содержимое, обычно для элементов вне экрана.

## Как обычно используют

Часто вместе с ним добавляют `contain-intrinsic-size`, чтобы браузер заранее знал примерный размер блока и не было сильных сдвигов layout при появлении контента. Это помогает сохранить стабильность страницы при ленивом рендеринге.

```css
.section {
  content-visibility: auto;
  contain-intrinsic-size: 500px;
}
```

## Когда это полезно

Это хороший выбор, если у вас:

- длинная страница с большим количеством секций;
- много карточек или комментариев;
- тяжёлые блоки, которые не видны сразу;
- важно ускорить первую отрисовку и взаимодействие с верхней частью страницы.

## Когда не стоит полагаться только на него

`content-visibility` не уменьшает количество DOM-узлов, он лишь откладывает рендеринг. Поэтому для **очень больших списков** или таблиц виртуализация через `react-window` всё равно может быть эффективнее.

# content-visibility vs react-window

`content-visibility: auto` и `react-window` решают похожую задачу, но на разных уровнях. CSS просит браузер пропускать рендеринг невидимых блоков, а `react-window` вообще не держит в DOM всё содержимое списка, а создаёт только видимое окно элементов.

## В чём разница

`content-visibility` оставляет все элементы в DOM, просто откладывает layout, paint и часть вычислений для тех, что вне экрана. Это удобно для длинных страниц и больших секций, где контента много, но пользователь видит только верхушку.

`react-window` делает виртуализацию: в DOM одновременно существуют только строки из viewport и небольшой запас вокруг него. Поэтому библиотека уменьшает не только работу браузера, но и нагрузку на React и на память.

## Когда достаточно CSS

Если у вас длинная статья, лента карточек или набор секций на странице, `content-visibility: auto` часто даёт хороший выигрыш почти без кода. Он особенно полезен, когда элементы уже в DOM, но не нужны прямо сейчас.[^12]

Пример:

```css
.card {
  content-visibility: auto;
  contain-intrinsic-size: 300px;
}
```

## Когда лучше react-window

Если у вас очень большой список, таблица, чат или тысячи однотипных строк, `react-window` обычно эффективнее. Он не даёт браузеру и React даже пытаться работать со всем списком сразу, поэтому сильнее экономит DOM и JS-работу.

Пример:

```jsx
import { FixedSizeList as List } from "react-window";

<List height={400} width={300} itemCount={10000} itemSize={36}>
  {Row}
</List>;
```

## Что выбрать на практике

- Для длинных страниц и секций — `content-visibility`.
- Для огромных списков и таблиц — `react-window`.
- Для сложных приложений иногда имеет смысл сочетать оба подхода: виртуализация для списка и `content-visibility` для тяжёлых вложенных блоков.

## Коротко

`content-visibility` — это “не рендерить то, что пока не видно”. `react-window` — это “вообще не создавать то, что не видно”. Поэтому CSS не заменяет виртуализацию полностью, а закрывает более простой и лёгкий класс задач.
