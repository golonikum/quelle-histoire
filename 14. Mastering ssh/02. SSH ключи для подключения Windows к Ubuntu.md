# SSH ключи для подключения Windows к Ubuntu

## 1. Проверьте OpenSSH на Windows

В PowerShell:

```powershell
ssh -V
```

Если команда не найдена — Параметры → Система → Дополнительные компоненты → Добавить → «Клиент OpenSSH».

## 2. Сгенерируйте ключ

```powershell
ssh-keygen -t ed25519 -C "windows-pc"
```

Путь оставьте по умолчанию (`C:\Users\<Вы>\.ssh\id_ed25519`).

Про парольную фразу: если оставить пустой — подключение будет вообще без ввода чего-либо, но укравший файл ключа получит сервер. Компромисс — задать фразу и разблокировать её один раз за загрузку через ssh-agent (шаг 3). Рекомендую второе.

## 3. Настройте ssh-agent (если задали парольную фразу)

PowerShell **от администратора** — один раз:

```powershell
Set-Service ssh-agent -StartupType Automatic
Start-Service ssh-agent
```

Дальше в обычном PowerShell:

```powershell
ssh-add $env:USERPROFILE\.ssh\id_ed25519
```

Фразу спросят один раз, ключ останется в агенте.

## 4. Скопируйте публичный ключ на сервер

`ssh-copy-id` в Windows нет, поэтому так (пароль от `sshuser` спросят в последний раз):

```powershell
$key = Get-Content "$env:USERPROFILE\.ssh\adminvps_flaptop.pub"
ssh sshuser@78.17.11.139 "mkdir -p ~/.ssh && chmod 700 ~/.ssh && echo '$key' >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
```

Передача ключа аргументом, а не через пайп, — чтобы PowerShell не подсунул UTF-16 и BOM в `authorized_keys`.

## 5. Проверьте вход

```powershell
ssh sshuser@IP_СЕРВЕРА
```

Должно пустить без пароля сервера. **Не закрывайте эту сессию**, пока не закончите шаг 7.

## 6. Сделайте алиас (удобство)

Создайте файл `C:\Users\<Вы>\.ssh\config`:

```
Host vps
    HostName 1.2.3.4
    User sshuser
    IdentityFile ~/.ssh/id_ed25519
```

Теперь достаточно `ssh vps`. Файл без расширения.

## 7. Отключите вход по паролю на сервере

В открытой сессии:

```bash
sudo nano /etc/ssh/sshd_config
```

Проверьте:

```
PubkeyAuthentication yes
PasswordAuthentication no
PermitRootLogin no
```

Важный момент для Ubuntu: настройки могут перебиваться файлами из `/etc/ssh/sshd_config.d/` (у многих хостеров там лежит `50-cloud-init.conf` с `PasswordAuthentication yes`). Проверьте:

```bash
sudo grep -r PasswordAuthentication /etc/ssh/sshd_config.d/
sudo sshd -t   # проверка синтаксиса
sudo systemctl restart ssh
```

Затем в **новом** окне PowerShell попробуйте `ssh vps`. Работает — старую сессию можно закрывать.

---

Если позже появится ошибка «Permissions for ... are too open» (обычно после копирования профиля), лечится так:

```powershell
icacls "$env:USERPROFILE\.ssh\id_ed25519" /inheritance:r /grant:r "$($env:USERNAME):(R)"
```
